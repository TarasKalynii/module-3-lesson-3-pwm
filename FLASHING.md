# Прошивання ESP32-S3 та перегляд логів

У VS Code натисни **Cmd+Shift+B**: дія «ESP-IDF: Прошити USB та показати логи»
збере проєкт, запише прошивку, автоматично запустить програму та відкриє монітор.
Також доступна кнопка **ESP-IDF: Execute Custom Task**.

У терміналі з поточної папки:

```bash
bash tools/idf.sh flash-monitor
```

Скрипт активує встановлений ESP-IDF 6.1 та знаходить ESP32-S3 за USB-серійним
номером E8:3D:C1:F2:9D:A4. Перед записом закриває монітор цього проєкту
та OpenOCD єдиної підключеної ESP32-S3. Сторонні власники порту не закриваються.
Паралельні збірки та прошивання блокуються.

Після запису скрипт очищає тимчасовий прапорець примусового USB download mode
та виконує watchdog reset. Монітор відкривається з --no-reset, щоб повторно
не скидати плату. Натискати RESET/EN після нормального прошивання не потрібно.
Цей механізм не змінює eFuses. Якщо BOOT фізично затиснутий або GPIO0 притиснутий
до GND, потрібно усунути це підключення.

Журнали збірки, запису та автоматичного запуску: build/flash-logs/.
Логи програми відображаються наживо в терміналі. Вихід із монітора: **Ctrl+]**.
Наступне прошивання може закрити попередній монітор автоматично.

Окремі дії:

```bash
bash tools/idf.sh build        # лише збірка
bash tools/idf.sh flash        # запис і автоматичний запуск без монітора
bash tools/idf.sh monitor      # монітор уже запущеної програми без скидання
```

monitor самостійно не запускає програму, якщо плата вже в download mode:
у такому випадку використовуй flash-monitor.

Очікувані повідомлення: SAFE: ESP32-S3 SAFE STARTED, PWM initialized,
GPIO initialized, NEW ATTEMPT. Далі кожні 5 секунд у звичайному циклі
з'являється SAFE: HEARTBEAT зі станом сейфа, GPIO та використаними спробами.

Для доступу до плати процес повинен мати права на /dev/cu.usbmodem*.
При Operation not permitted запис із обмеженого середовища не виконується;
команду слід запустити у звичайному локальному терміналі.
